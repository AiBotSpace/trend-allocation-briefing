# 定时任务：每日趋势与配置简报

- 任务 id：`weekly-trend-allocation-briefing`（历史命名，实际为每日任务）
- 标题：每日趋势与配置简报
- 日程：工作日（周一至周五）09:00，北京时间；节假日休市跳过
- 下次运行：第 2 期，2026-11-18（周三）09:00
- 交付：本聊天（链接 + 摘要）、飞书（完整版全文）、Telegram（完整版全文，分段）

## 执行步骤（任务正文）

每日趋势与配置简报（新一期，期号 = 上期 + 1）。第 1 期已于 2026-11-17 交付
（Google Doc，数据截至 2026-11-16 收盘）。每期是一份新的 Google Doc，
旧版保留不覆盖。工作日每天早上发送。

1. 先读状态文件 `state.json`，了解上期的指数点位、回报、配置对照、市场情绪基线
   与趋势系统信号。本期只写变化与新增信号，不重复上期完整背景；连续 3 个交易日
   无实质变化时，在简报中说明无须调整关注点，并更新无变化计数。
2. 检索最新公开市场数据，口径为最近一个完整交易日的收盘（周一上午运行取上周五
   收盘；遇长假取最近交易日）。检索：上证指数、深证成指、沪深300、创业板指、
   科创50、中证500、中证1000、上证50、北证50收盘点位与涨跌；两市成交额；美股
   三大指数收盘；中国 10 年期／2 年期国债收益率、美国 10 年期国债收益率；美元兑
   人民币中间价、美元指数；黄金、原油（WTI／布伦特）、铜期货报价；本周重要事件
   （财报、经济数据、政策会议）。另检索市场情绪指标（涨跌家数、涨停／跌停家数、
   连板高度与晋级率、炸板率、昨日涨停溢价、两融余额、情绪温度）与趋势数据（主要
   指数收盘价 vs MA20／MA60／MA250、52周高低位置、站上MA20的ETF占比）。如当日
   为A股休市日（法定节假日），则不新建文档、不发送，只在 `state.json` 记录跳过原因。
3. 严格区分事实、推断、未知：所有数字须有可核对的公开来源（主要指数收盘点位至少
   两个独立来源交叉核对）；未核实处明确标注未知，绝不编造价格或回报；不写确定性
   投资建议；不使用用户个人持仓数据，只对照公开的全天候参考组合（股票 30%／长期
   债券 40%／中期债券 15%／黄金 7.5%／大宗商品 7.5%）。注意：北向资金当日净买入
   自2024年8月起不再披露，不要引用聚合站声称的净买入额；均线值须注明日期，引用
   非当日均线值时明确标注并列入未知。
4. 生成简报文档：复用 `generator/` 下最新一期的生成器作为 python-docx 模板，更新
   内容后生成新的 docx，用 LibreOffice 转 PDF 并逐页检查渲染（表格、编号、中文无
   乱码），修正后再发布。简报结构固定：结论（前置）、事实（A股指数表、市场情绪、
   近期调整对照、外围与宏观）、全天候参考组合对照、趋势系统与仓位、推断、未知、
   本周关注、数据来源。趋势系统规则固定（见 `state.json` 的 trend_system）。
5. 发布：创建新 Google Doc（标题格式：趋势与全天候配置简报 · 第N期（YYYY年MM月DD日）），
   用 Drive 上传 docx 转换填充；再读回验证（章节、表格、关键数字齐全）后才算完成。
6. 更新 `state.json`（新一期的点位、回报、情绪基线、趋势信号与仓位、文档 ID 与链接、
   无变化计数、未解决的未知项）。
7. 同步发送：新一期简报的链接与核心变化摘要发到本聊天；完整版全文发到飞书与
   Telegram（Telegram 单条上限 4096 字符，按段落切分；见 `generator/extract_text.py`）。
   某处发送失败时在本聊天里说明原因，不要静默。
8. 推送本仓库：按 GitHub 连接器的 snapshot-push 流程，将本期新增/变更的文本文件
   提交到本仓库（`main` 分支）。
